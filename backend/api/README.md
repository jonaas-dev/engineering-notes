# API design

Three notes from the same idea: an API is a user interface, and its users are engineers
under time pressure.

- [Designing a Secure API](designing-a-secure-api.md) — contract first, then the layers,
  CQRS and OAuth 2.0 flows that follow from it.
- [Designing APIs for humans: Object IDs](designing-apis-for-humans-object-ids.md) — why
  integer row ids leak your row count and invite enumeration attacks, and what to use instead.
- [Designing APIs for humans: Error messages](designing-apis-for-humans-error-messages.md) —
  a good error says what went wrong, where, and what to do about it. Stripe's is the example.
