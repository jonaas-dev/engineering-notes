# SOLID

Two notes, and they disagree with each other on purpose. The principles are worth knowing;
so is the case against taking them literally.

- [From STUPID to SOLID Code](from-stupid-to-solid-code.md) — the STUPID acronym
  (singleton, tight coupling, untestability, premature optimization, indescriptive naming,
  duplication) walked through, then SOLID as the answer to each.
- [Why Every Element of SOLID is Wrong](why-every-element-of-solid-is-wrong.md) — Dan North's
  talk: "one reason to change" as a pointlessly vague principle, and what to use instead.

There is a rebuttal to that talk worth reading alongside it:
[Why Every Single Argument of Dan North is Wrong](https://www.entropywins.wtf/blog/2017/02/17/why-every-single-argument-of-dan-north-is-wrong/).
